Overview

The start page has four parts, from top to bottom:

  1. Choose your data source: upload your own files or pick an example dataset.
  2. Preprocessing: which representations of the sample to build (pseudospots, cells).
  3. Load data, with a status line below it.
  4. Loading progress: one progress bar per task.

When every task has finished, the status line reads Done and the viewer opens. Everything you do afterwards lives in your browser session: reloading the page brings you back here, and nothing is saved between sessions (except cached segmentation results, see below).

The files you need

One Visium HD sample, as produced by 10x Genomics Space Ranger, at one bin size:

FieldFile in the Space Ranger outputNotes
1. Expression data (.h5) binned_outputs/square_XXXum/filtered_feature_bc_matrix.h5 Counts of every gene in every bin under the tissue.
2. Positions data (.parquet) binned_outputs/square_XXXum/spatial/tissue_positions.parquet Where each bin is on the image. Must come from the same square_XXXum folder as the .h5.
3. Resolution (µm)the XXX of that folder: 2, 8 or 16 Bin size of the two files above.
4. Tissue imagethe full-resolution image given to Space Ranger .btf, .tif/.tiff or .png. Used as the background, to compute physical distances and for cell segmentation.
Which bin size? 2 µm is the native resolution and the largest data (millions of bins; loading takes minutes). 8 and 16 µm load faster. Whatever you choose, the viewer can still sum bins into larger cells while you explore (see bin resolution).

Choosing a data source

Upload files

Fill in the four fields above with Choose file…. Each file starts uploading as soon as you choose it, with its progress shown below the fields; multi-gigabyte files are supported (up to 20 GB each on the public server). Wait until every file reads Uploaded, then click Load data. Choosing another file replaces the current one, and Cancel upload / Remove clears a field. Closing the browser tab cancels the session's uploads and running analyses and deletes its files from the server.

Load example

Pick one of the datasets configured on this server. Nothing to upload; a good way to learn the platform.

What to compute

Bins (always)

The bins of your files are always loaded. They become the Bins layer of the viewer.

Generate Visium v2 pseudospots

Builds a grid of 55 µm spots like standard Visium (v2) and aggregates the bins under each spot. Useful to compare with standard Visium data, or with each other in the Comparison panel. They become the Spots layer.

Cell segmentation

Each method you tick finds cells (or nuclei) in the tissue image. Then every bin lying entirely inside a cell is assigned to it, and the cell's expression is the sum of its bins. Bins inside more than one cell are left out. Every method becomes its own cells layer (a tab in the Cells section, with its own outline color), so you can compare methods on the same tissue.

  • Tick several methods to compare them. Two run at the same time; the others wait, shown as Queued.
  • Settings appear when you tick a method. Leaving a field empty uses the method's own default.
  • Results are cached next to the dataset, per image, method version and settings: loading the same sample with the same settings again is instant.
  • Methods run in their own containers or Python environments on the server. Which methods are offered depends on how the server you are using is set up, so some may be missing or fail on a given server. The first run of a method may take longer while its software is prepared.

The methods and their settings

MethodWhat it findsSettings
StarDistNuclei, with a deep-learning model trained on H&E images. Probability / overlap thresholds: lower finds more nuclei (empty = calibrated values). Normalization low / high percentile (as labeled in the form): image contrast stretch. Block size: image tiles processed at once (memory vs. speed).
CellposeWhole cells (cyto3) or nuclei (nuclei). Expected diameter (µm): typical cell size. Flow threshold: higher keeps more, less regular cells. Cell probability threshold: lower finds more and larger cells. Block size.
Watershed (baseline)Nuclei, with classical image processing (no model). Smoothing, Threshold factor (higher keeps fewer, darker nuclei), Min. distance between nuclei, Min. nucleus area, Block size.

Segmenting a whole slide on a CPU takes from minutes (watershed) to much longer (StarDist, Cellpose).

Troubleshooting

SymptomWhat to do
"Please upload …"A required file is missing (see the four fields above).
Bins load but look misplacedThe positions file and the .h5 come from different bin sizes, or the image is not the one given to Space Ranger.
A segmentation bar failsThe bar shows the reason. The other layers still load, so you can continue without that method. If the problem persists, report it (see below).
"killed, most likely out of memory"The server ran out of memory for that method. Try a smaller block size, a coarser bin size, or another method.
"No module named …" / container pull errorsThe method is not available on this server. Choose another method.

To report a problem, open an issue at github.com/LuisAlonsoEsteban/VisiumVisualizer/issues or write to laesteban@unav.es. Include the message shown on the progress bar, the method and settings you used, and the dataset (example name or bin size).

Drag the edges between the panels (and the top edge of the results) to resize them. The ? button next to each tool's title explains it and links to the matching section here. Click the name at the top left, or About, to go back to the overview page; Resume workspace there brings you back to your analysis.

The map

The tissue image is drawn with your layers on top. Scroll to zoom and drag to pan. Only the visible region is loaded, so new areas fill in as you move. Hover tooltips are off by default: turn them on with the hover button of the plot toolbar, then hover an observation to see its values: the gene shown, and its group and cluster when there are any.

The image keeps its original orientation and aspect ratio. Transparent padding supplies the square tile canvas, and bin rectangles follow the tissue grid's rotation. Original image files and annotation coordinates are preserved.

Image opacity, in the overview at the bottom left of the map, fades the tissue image so the layers stand out.

Differential-expression and metadata-comparison results open below the map; drag their top edge to give the map more or less room.

Cells layers are drawn at every zoom; zoomed out, their outlines are simplified to the detail the screen can show.

Measuring distances

Pick the ruler in the toolbar and click two points: a dashed line joins them and its length is shown in µm (or mm). Drag either end to adjust; a third click starts a new measurement. The eraser button next to it clears it.

Bin resolution

The box at the top right of the map shows the bin level in use (e.g. BINS · 4 × 4). Click + to unfold it and control how bins are drawn:

  • Dynamic · follow zoom (default): zoomed out, bins are summed into larger cells (2 × 2, 4 × 4, 8 × 8, 12 × 12 bins) so the map stays fast; zooming in shows native bins again.
  • Fixed · …: always draw one level.

Aggregates are blocks of neighboring array rows and columns, anchored at array index zero. Their membership stays the same as you pan and zoom; incomplete edge blocks use the bins present.

The panel also shows the size of the drawn cells, their rotation and the native bin size. While bin clusters are shown, their computed level is the minimum. Dynamic zoom can choose coarser levels, and fixed choices below that minimum are hidden. Coarser bins show their most common cluster label. Click − to fold the panel into a single line and + to unfold it.

Overview and coordinates

The overview (bottom left of the map; fold it with −) shows the whole slide, with a rectangle marking the region the map is showing. Copy coordinates, below it, copies the region shown on the map as x0,y0,x1,y1 in full-resolution image pixels (the same system as Space Ranger's pxl_col_in_fullres / pxl_row_in_fullres), e.g. to crop the image elsewhere. The coordinates refer to the original image, excluding the canvas padding; for a rotated image they are the bounding box of the region.

Layers

Each representation of the sample is a layer: Spots (pseudospots), Bins and one Cells layer per segmentation method. Every layer has the same tabs: Display, Clustering, Groups, ROIs, DE, Deconv., Metadata and Params. An observation is one spot, bin or cell with counts: bins, pseudospots and cells without any counts (e.g. bins outside the tissue) are left out when the data loads, which keeps the map fast. An observation whose shown value is missing (e.g. an empty metadata entry) is drawn in gray.

Display tab: showing a layer

  • The eye next to each layer in the layer list shows or hides the whole layer.
  • Opacity: maximum opacity. When coloring by a gene, opacity follows its expression up to this value; with categories (clusters, groups) every observation uses it.
  • Clear selection: deselect the layer's observations on the map and in the embedding.
  • Download .h5ad: the layer as an AnnData file with its counts and everything computed so far in the session: clusters, groups and deconvolution results.

Display tab: coloring

  • Gene / Metadata: start typing and pick a gene or a metadata column from the suggestions.
  • Expression values: how genes are displayed. Counts are the raw UMI counts; Normalized divides each observation by its total counts and multiplies by 10,000; Log-normalized applies log(1 + x) to the normalized value, which compresses highly expressed genes and makes differences in sequencing depth across the tissue less prominent. Aggregated bins are normalized by their own total counts. The choice applies to the map, its color scale and tooltips of this layer only; clustering, differential expression and group conditions always use counts.
  • For genes and numeric columns, observations use one color chosen with the color picker; opacity follows the value.
  • For categorical columns (clusters, groups, …), the single-color picker is disabled and each category gets its own color. Clusters and groups keep the same colors everywhere: map, lists and DE results. Groups and clusters never share a color.

Clustering tab

Groups observations by similar expression using the selected algorithm.

  1. Choose Leiden, K-means, DBSCAN, HDBSCAN, Gaussian mixtures or agglomerative clustering. For Leiden, higher resolution gives more, smaller clusters. K-means, mixtures and agglomerative clustering take a number of clusters. DBSCAN takes an epsilon distance in PCA space and minimum samples; HDBSCAN takes minimum cluster size and minimum samples. Mixtures offer covariance types, and agglomerative clustering offers linkage choices.
  2. Click Run clustering. Behind the scenes: normalization, log transform, highly variable genes, then PCA. Leiden also builds a neighbor graph. Preprocessing and clustering results are cached for reuse with the same parameters.
  3. As soon as clustering finishes, the map is colored by cluster and the list of clusters appears, each with its number of observations.
  4. Then the marker genes (Wilcoxon test, each cluster vs the rest) are ranked in the background: the top five fill in under each cluster, and the top ten appear in the Summary. Run clustering is available again when they are ready. Density-method outliers appear as Noise. Noise and groups with fewer than two observations have no marker ranking; neither does a single resulting group.

Tick or untick clusters (or use Select all / Deselect all) to show or hide them on the map. For bins, clustering runs at the displayed level and the map can show that level or coarser bins while the clusters are shown.

Deconvolution tab

Optionally upload a single-cell .h5ad or .h5 reference on the initial loading screen, when uploading your own spatial data. Examples use a configured local reference when available and otherwise run without one; reference upload controls are hidden for all examples. A supplied reference is loaded once and available in every layer's Deconvolution tab. AnnData .obs annotations load automatically, including from files named .h5. The Human CRC example loads the count matrix, SingleCell_MetaData.csv and P1CRC_Metadata.parquet already stored on the server, without uploads. The CSV annotates the reference cells; deconvolution defaults to Level1, with Level2 and the other reference columns available in the selector. The Parquet labels spatial bins and is attached to the spatial expression data. Standard 10x .h5 files contain counts without cell-type labels: upload an annotation CSV or Parquet file alongside the reference, with matching cell barcodes in the first column and annotations in the other columns. Parquet may also store barcodes in its index or a column named barcode. These annotation columns are offered in the tab. Choose the cell-type annotation column, then run deconvolution. Both datasets need matching, unique gene identifiers and nonnegative linear expression in .X, not log counts.

Choose NNLS, spacexr (RCTD), cell2location, MuSiC, or CIBERSORTx in the method selector. Controls change with the method. NNLS estimates expression mixture fractions from library-normalized reference profiles; these are not calibrated cell counts. spacexr (RCTD) (Cable et al., 2022) needs raw integer counts and at least two reference cell types. Its main settings are RCTD mode (doublet, the default, fits at most two types per observation; full allows all types; multi allows up to Maximum types per observation, default 4), Minimum target UMIs (default 100; observations below it stay unassigned), the normalization and regression gene cutoffs, and the reference filters Minimum reference cell UMIs (default 100), Maximum reference cells per type (default 10,000) and Minimum reference cells per type (default 25). Rejected observations and uncertain doublets remain unassigned. RCTD fits the whole layer and can take hours on large layers. While a method runs, Cancel next to Run deconvolution stops it and keeps no result; the tab is free for another run at once. cell2location requires an expected cell count per location and offers posterior mean abundance alongside relative fractions. MuSiC requires a donor/sample annotation containing multiple subjects. CIBERSORTx generates a signature from the uploaded reference; it can be offered only when the server operator has installed it and supplied their own CIBERSORTx credentials.

Which methods appear depends on the server you are using: a method missing from the selector is not installed there. Deconvolution runs in the background and continues only while your browser session is open; long runs (for example RCTD on a whole 8 µm sample) need the tab to stay open until they finish.

Each run analyzes all native observations in the layer in the background. Empty observations remain unassigned. Choose a saved run, readout, and cell type to show results on the map. Coarse bins average fractions and sum expected cell abundance. Numbered metadata columns retain every run; the latest fractions remain in obsm['deconvolution'] and their details in uns['deconvolution']. All run metadata is retained in uns['deconvolution_runs'], including parameters and output units, and is included in exported AnnData files.

ROIs tab

Each layer has its own session-only ROIs. Enter a name or leave it blank for an automatic name. Choose Bounding box, Lasso, or Seed + radius and click Draw. Drag a box or lasso on the map; for a radius ROI, set the radius and click the seed. The radius is in µm when physical calibration is available and full-resolution pixels otherwise. Uniform image scaling preserves circular radii in original-image physical units.

On a bins layer, choose Find barcode / bin index as the seed source to search native barcodes with autocomplete. Start typing the barcode and choose an exact suggestion, or paste the complete barcode. Its native bin center becomes the seed, independently of the current viewport or displayed aggregation. Selecting a barcode previews the region and brings it into view; changing the radius updates the draft. Preview barcode rebuilds and focuses it. Click Save ROI to keep the region; its saved entry records the seed barcode.

For a bins layer, Seed + radius also offers All bins in a group. Select an existing group to use every native member bin's center as a seed, regardless of displayed bin aggregation or viewport. Their radius neighborhoods are united into one ROI, retaining disconnected pieces and holes. Choose Full ROI to keep the full neighborhood, or ROI minus group to subtract the source-group bin footprints and exclude those bins from ROI membership. If subtraction leaves no region, increase the radius. The preview updates automatically when the group, radius, or ROI region changes; Preview group also rebuilds it on demand. Complex outlines are prepared in the background and displayed as bounded-resolution overview images so large groups do not send millions of polygon vertices to the browser. Zoomed edges may look pixelated; saved geometry, membership, selection, and generated groups still use the exact region. The source-group footprint is reused when only the radius changes. Save ROI commits that single region. Other group members and nearby bins can belong to the ROI through the normal shape-intersection rule.

A white outline previews the draft. Save ROI commits it; Cancel discards it. Membership is computed over all native, sequenced observations whose shapes intersect or touch the region, independently of visible data and bin aggregation. Empty ROIs can still be saved and focused.

Focus fits the viewport with a small margin. Select highlights the members on the map and in embeddings; aggregated observations highlight when any member is selected. Create group makes a fixed-membership group for existing group controls and DE comparisons. Deleting an ROI also deletes its generated group and clears affected DE results. If you delete just the group, you can recreate it from the ROI. Hide outlines with the Outline checkbox. Saved shapes cannot be edited or exported in this version; redraw to replace them.

Groups tab

Define your own groups of observations from conditions on genes or metadata.

  1. Build conditions: choose a gene or metadata column, an operator (>, <, >=, <=, ==) and a value, then + Add condition. From the second condition on, choose how it combines: AND or OR. Conditions are applied in order, left to right. Genes and numeric columns take a number; genes are compared on their raw counts. Categorical columns (e.g. a deconvolution run's dominant cell type) accept only == and a category name, e.g. deconv_1:most_abundant == Tumor II. The added conditions are listed as, e.g., EPCAM > 2 AND COL1A1 > 0. Clear starts over.
  2. Name the group and click Create group.
  3. The Created groups list shows each group with its size, colour and, for combined groups, how it was made. Tick or untick groups to show or hide them on the map; ✕ deletes a group.
  4. Combine groups makes a new group from existing ones: the intersection (A ∩ B, in both), union (A ∪ B, in either), difference (A − B, in A but not in B), or the complement of one group (not A, every sequenced observation outside it). Tick Take the opposite set to keep everything outside an intersection, union or difference, e.g. not (A ∩ B). The number of observations is shown before you create it. The new group keeps its members even if A or B change or are deleted later, and can be used like any group in DE, ROIs and Metadata comparison.

An observation in several groups is drawn with the group created last. Hiding a group on the map does not affect differential expression.

DE tab: differential expression

Finds the genes that differ between groups and/or clusters.

  1. Compare: tick groups and/or clusters. You can mix them, e.g. one group and one cluster.
  2. Against:
    • vs Rest: each ticked group or cluster against all other observations.
    • Between selected: the ticked ones against each other. Observations that belong to more than one of them are left out (the status line says how many).
  3. Resolution (bins only): test native bins or aggregated cells (summed counts) of a level. Displayed level follows the map. An aggregated cell belongs to a group or cluster when more than half of its bins do.
  4. Click ▶ Run DE. The status line shows the steps and the elapsed time.

Results appear below the map:

  • A table of genes with, per group or cluster, the log2 fold change (green up, red down) and the adjusted p-value (white when < 0.05). Click a column header to sort (again to reverse); the search box finds any gene, not only the 200 rows shown.
  • Plots of the top genes of each group or cluster: a dot plot for spots (fold change, and the share of observations expressing the gene), violin plots for bins and cells. Hover dots or violins for gene, group, adjusted p-value, fold change and expression statistics. Use the plot toolbar to pan, zoom, select, reset or save. Click a legend entry to hide or show that comparison; violin hover also reports the median and quartiles.

Method: Wilcoxon rank-sum test on log1p counts normalized to 10,000 per observation, genes detected in at least three observations, Benjamini–Hochberg adjusted p-values. Each group or cluster needs at least three observations.

Metadata tab: metadata comparison

Select two or more groups and/or clusters, choose numeric metadata columns, and click Compare metadata. Alternatively, tick The rest and select one or more groups/clusters: each gets a separate plot against observations outside every defined custom group (including hidden or unselected groups) and outside the compared set itself, as in DE against the rest. The remainder is computed over native bins/cells/spots, without creating another stored group. When the groups and the compared set cover the whole layer, The rest is empty and the comparison reports this. Saved deconvolution runs appear as presets for cell-type fractions and, when available, abundance. Choose Mean (default) or Median.

Results appear below the map, in the same results area used by DE. Each cell type or metadata column has one horizontal bar per group: labels on the y-axis, values on the x-axis, and a color for each group. Hover for values and valid-observation counts. Legend clicks hide or show groups. Running DE or another comparison replaces the displayed result.

Metadata comparisons use native observations, independently of the viewport and bin display aggregation. Non-finite values are omitted per column, with counts reported in the results. Overlapping observations contribute to every group they belong to. Deconvolution fractions are averaged without renormalizing over the selected cell types. These are descriptive comparisons, without significance tests; use the separate DE tab for gene-expression testing.

Params tab: drawing parameters

Extra drawing parameters of the layer: fill opacity, line width, line colour and line opacity. Color and opacity themselves are set in the Display tab.

  • Fixed: one value for all observations, plus a value for those whose data is missing.
  • From data: a gene or numeric column scaled between Min and Max; for colours, a categorical column (one colour per category). Optionally show the column on hover.
  • Apply redraws the map at the same view; Reset returns the attribute to its default.

Summary panel

The Summary tab of the right panel.

The table compares the layers: number of observations, mean UMIs (counts) per observation and UMIs per µm². Each layer then has:

  • QC: distributions of % mitochondrial reads and genes per observation, and UMIs against % mitochondrial reads and against genes.
  • Markers: the top ten marker genes of each cluster of the last clustering, with score, adjusted p-value and log fold change.

Embeddings

The Embeddings tab of the right panel: choose the layer, then PCA, UMAP or t-SNE and click Run embedding. Embeddings use the same preprocessing as clustering, so a UMAP after clustering only computes the UMAP itself. For bins they use the displayed aggregation level. Select points in the embedding to highlight the same observations on the map, and the other way round.

Color by colors the points by a gene or a metadata column. Genes use a color gradient on the layer's Expression values scale; clusters and groups keep the colors assigned to them, and other categories get one color each. When a clustering finishes, the embedding switches to the new clusters. Turn on hover in the plot toolbar, then hover a point to see its value.

Comparison

The Comparison tab of the right panel compares two layers of the same tissue, e.g. pseudospots vs bins, or two segmentation methods.

  1. Sample 1 / Sample 2: the two layers, in either order; results are labeled in the order you chose. The layer with larger geometries (the low-res layer) is the reference, and local metrics are written to it.
  2. Match high-res geometries that are inside or overlapping each low-res geometry, and the Min. coverage a low-res geometry needs to be compared.
  3. Optionally, the clusters and cell types of each sample (deconvolution proportions or a label column, on either sample), to compare them too.
  4. Click Compare samples.

Results come in three tabs. Global lists summary metrics; hover ⓘ or click a metric for its explanation. Local has per-geometry metrics: show one on the map, or plot two against each other and select points to find them on the map. Genes lists per-gene agreement; click a gene to show it on both layers.

Your own methods (plugins)

Every cell segmentation and deconvolution method in the platform is a plugin: a folder with a manifest (title, version, container image and parameters) and a script that runs the method. The interface is built from the manifest, so a new method needs no change to the viewer:

  • Segmentation plugins are listed on the loading screen under Cell segmentation. Tick one or several: each becomes its own Cells · method layer, so methods can be compared side by side, on the map or in the Comparison panel.
  • Deconvolution plugins are listed in each layer's Deconv. tab. Every run is saved with the layer and can be shown on the map, used to build groups, or compared in the Metadata tab.
  • The settings form, its limits and help texts come from the manifest. The method's description, documentation link and citation are shown with it: please cite the methods you use.
  • Plugins run in their own container or environment, and their results are cached per input, method version and settings: rerunning the same settings is instant.

Adding a method. If you develop a segmentation or deconvolution method, you can add it by copying a template plugin, editing its manifest and script, and restarting your local copy of the platform. The plugin guide walks through both kinds step by step. To make a method available on the public server, propose it with a New method plugin issue or a pull request. The public server only runs reviewed plugins from the repository; visitors cannot upload code.

A typical analysis

  1. Color: type a gene you know to check the tissue and the data line up.
  2. Clustering: choose and run a clustering algorithm; look at the clusters on the map and their marker genes.
  3. Groups: define groups of observations from conditions, e.g. EPCAM > 2 for epithelial (tumor) bins in the Human CRC example.
  4. DE: compare a group with a cluster, or clusters with each other, and browse the table.
  5. Embeddings: run a UMAP and select a cluster to see where it lies in the tissue.
  6. With segmented cells, compare methods side by side, or against bins in Comparison.
