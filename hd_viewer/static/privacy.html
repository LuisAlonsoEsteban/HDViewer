HDVIEWER

Privacy, data retention and requirements

HDViewer is free and open to all users. It needs no account, login or e-mail address, and it uses no analytics or tracking.

What happens to your data

  • Each browser session gets its own private folder on the server. Uploaded files, intermediate results (image tiles, segmentation, deconvolution) and exports are only reachable from that session.
  • The folder and everything in it is deleted when the session ends:
    • 1 minute after you close the last tab of the session (a page reload keeps it);
    • after 30 minutes without any activity;
    • whenever the server restarts.
  • Exported .h5ad files are written under a random name in that folder and deleted as soon as they have been sent to your browser.
  • Your data is never shared with other users or third parties, and is not used for any purpose other than the analyses you run.
  • Results computed for the example datasets (for example a deconvolution run) may be cached on the server so that later visitors get them faster. Results of uploaded data are never cached beyond the session.

Cookies

HDViewer sets a single cookie, hdv_sid: a random session identifier that links your browser to its private folder. It is deleted when you close the browser. No permanent or third-party cookies are set by HDViewer. The university network in front of the server may add its own technical load-balancing cookie.

Server logs

Like any web server, the public instance keeps standard access logs (IP address, time and requested address) for security and to count usage. They do not contain your data or file contents.

Hosting and contact

The public instance at hdviewer.unav.edu is run by the Computational Biology group of Tecnun, University of Navarra (Spain). For questions about your data, write to laesteban@unav.es.

If you prefer not to upload data, you can run the same application on your own computer: see the installation instructions.

Browser requirements

HDViewer runs in recent desktop versions of Chrome, Edge, Firefox and Safari, with JavaScript and WebGL enabled. The analysis workspace is designed for desktop screens (at least 1280 pixels wide); phones and small tablets can open the overview and the documentation, but not use the workspace comfortably.
